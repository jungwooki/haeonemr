# MPS EMR 활동 이력

`emr_audit`에 로그인한 Firebase UID, 계정 이름, 서버 시각, 작업, 대상 ID를 저장합니다. 메모와 차트번호 수정은 변경 전후 내용도 보존합니다. EMR의 **활동 이력**에서 최근 100건을 확인합니다. 100건은 조회 범위이며 저장 이력은 자동 삭제하지 않습니다.

- 로그인 / 세션 재개 / 로그아웃
- 환자 목록·개별 환자·문진 열람
- 설문을 의료진 기록으로 접수
- 프리노트·간호사 메모·주치의 치료플랜 수정
- 차트번호 변경, 문진 삭제
- 앱의 복사 요청·클립보드 복사 완료·수동 복사 창, 인쇄 창 열기, 텍스트/JSON 저장 요청

기록 생성·메모 수정·차트번호 변경·문진 삭제는 이력과 같은 트랜잭션으로 저장됩니다. Firebase 규칙은 실제 UID와 이름을 검증하고 앱 사용자의 이력 수정·삭제를 차단합니다. 관리자 SDK는 규칙을 우회할 수 있습니다.

열람·복사·인쇄는 앱 동작을 계측합니다. 브라우저 메뉴, 운영체제의 복사, 실제 프린터 출력 완료를 모두 보장하는 감사 체계는 아닙니다. 네트워크가 끊긴 상황의 로그아웃은 이력 저장 실패 여부와 관계없이 보안을 위해 세션을 종료합니다. 과거 활동을 소급 생성하지 않습니다. 환자 제출 원본은 접수 시각을 유지하며 의료진이 가져올 때 해당 의료진의 접수 이력을 남깁니다.

계정은 `src/scripts/staff-accounts.js`의 이름과 가상 이메일을 매핑합니다. 개인별 초기 비밀번호는 웹 폴더 밖 `~/.config/sportsmps/backups/mps-emr/staff-accounts/MPS-EMR-초기계정.txt`에만 보관합니다. 배포에 포함하지 말고 각 직원에게 본인 정보만 전달합니다. 2026-10-03 사용자 요청으로 admin을 포함한 10개 계정에 공통 비밀번호를 적용했습니다. 로그인 화면은 이름 선택과 비밀번호 입력 방식입니다. 공통 비밀번호를 아는 사용자가 다른 이름을 선택할 수 있으므로 계정별 이력만으로 실제 작성자를 보장하지 않습니다.

검증: `tools/test_firebase_store.cjs`, `tools/test_plan_picker.cjs`, `migrations/verify_audit.py`. 마지막 스크립트는 별도 임시 문서만 생성·삭제하여 실서비스 규칙을 확인합니다.
